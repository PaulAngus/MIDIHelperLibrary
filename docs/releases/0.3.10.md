# MIDIHelperLibrary 0.3.10 — private Windows runtime

The Windows provider now embeds the Windows MIDI API DLL/PRI and the required
Microsoft C++ redistributable DLLs for x64 and arm64. Eligible Windows 11 builds
extract a verified content-addressed payload and load it by absolute path.
Windows 10 stays on the existing WinMM path and never extracts this payload.
The optional per-user API installer is obsolete for consumers of this package.
Explicit app-local API directories and diagnostic overrides remain supported.

Concurrent first launch accepts an identical file already extracted/loaded by
another process. Damaged private files are repaired from embedded resources.
`WindowsMidiDependencyReport.Write` reports actual loaded module paths without
opening, creating or sending MIDI ports. No app routing architecture is replaced.

51 audited offline core tests pass. All four Windows consumer EXEs pass fresh-cache
concurrent extraction, corruption repair and discovery on the development PC.
The C++ DLLs load from private directories, not System32. Static native dependency
closure passes. Clean Windows 10/11 and ARM64 execution remain unqualified.
See native/README.md under the Windows provider for provenance and servicing.

The build-only Publish-MacApplication.ps1 helper creates fresh self-contained
bundles and signs before archiving. End-user preparation scripts are unnecessary.
Developer ID notarization and clean Mac workflow acceptance are separate gates.
